# V9.1: what is added to the team's V9

V9.1 is **V9 exactly as the team made it** plus the server changes below. No frontend file was changed (no text, size, colour or screen).
Only these files differ from V9: backend/index.js, backend/package.json (+ lock), backend/services/oauth_identity.js, and the new files listed here.

## Added
- **Phone push through Firebase** (backend/routes/push_routes.js, services/push_service.js, models/push_token.js). When a notification is saved the server sends every registered phone one silent message, "ask for your notifications". With push working the phone app stops keeping its own always-open connection (less battery, and no permanent "SENETRY is running" card). It does nothing until FIREBASE_SERVICE_ACCOUNT is set; without it the app keeps working as before.
  - This was missing from V9 (V9 was built from the earlier 15 November server). The route reads the account from the login as `req.user.userId`, which is what V9's login middleware gives (the first push code read the wrong field and would have failed once signed in; it is tested now).
- **More than one app id per sign-in provider.** `MICROSOFT_CLIENT_ID` (and `GOOGLE_CLIENT_ID`) can now hold several ids separated by commas, so the website's Microsoft app and the phone app's Microsoft app both work. A single id works as before.
  - Set on the server: `MICROSOFT_CLIENT_ID=46da4e9c-7c6f-4009-a64d-7d7b49e71bfd,bcb63b65-8bff-4d91-9133-735263188e3b`

## Needed on the server
1. Deploy this folder's backend, run `npm install` in backend.
2. Set FIREBASE_SERVICE_ACCOUNT (key sent privately), MICROSOFT_CLIENT_ID (two ids, above), MESH_SIGNING_KEY (a long random secret), and optionally OPEN_METEO_API_KEY.

## Tests
